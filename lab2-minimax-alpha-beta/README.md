## 3. Теоретические сведения

### 3.1. Игровое дерево

Игровое дерево описывает игру двух игроков с противоположными интересами и полной информацией о позиции. Вершины соответствуют позициям, дуги — возможным ходам, корень — начальной позиции, листья — терминальным позициям (или позициям на предельной глубине поиска). Каждому листу сопоставляется число — оценка позиции для игрока MAX.

### 3.2. Принцип мини-макс

Значения вершин вычисляются от листьев к корню:

- для листа v(P) = f(P) (значение листа);
- для вершины игрока MAX: v(P) = max{v(P₁), …, v(Pₙ)};
- для вершины игрока MIN: v(P) = min{v(P₁), …, v(Pₙ)}.

Значение корня — результат игры при оптимальных действиях обоих игроков. Последовательность ходов, приводящая к нему, называется основным вариантом (оптимальным путём). Обычный мини-макс обходит все узлы дерева.

### 3.3. Альфа-бета отсечение

Альфа-бета — оптимизация мини-макса, которая не меняет значения корня, но сокращает число просматриваемых узлов. В рекурсию передаются два числа:

- α — наилучшее значение, уже гарантированное игроку MAX на пути к текущему узлу (начальное значение −∞);
- β — наилучшее значение, уже гарантированное игроку MIN (начальное значение +∞).

Узел MAX после каждого потомка повышает α, узел MIN понижает β. Если **β ≤ α**, остальные потомки узла не могут повлиять на результат, и их просмотр прекращается (отсечение).

### 3.4. Влияние порядка потомков

Эффективность альфа-бета зависит от порядка перебора ходов. В лучшем случае (сильнейшие ходы перебираются первыми) просматривается около b^⌈d/2⌉ + b^⌊d/2⌋ − 1 листьев, где b — ширина, d — глубина. Для b = 3, d = 6 это 27 + 27 − 1 = **53 листа из 729**. В худшем случае отсечений нет, и альфа-бета просматривает столько же узлов, сколько мини-макс.

## 4. Реализация

Программа написана на Python (файл `lab2_minimax.py`). Дерево хранится в виде вложенных списков: лист — целое число, внутренний узел — список из трёх потомков. Листья генерируются случайно (`random.Random(19)`, значения от 0 до 40). Обе функции рекурсивны и, помимо значения, возвращают оптимальный путь — список индексов выбранных потомков. Счётчики (посещённые узлы, листья, отсечения) хранятся в объекте `Stats`.

Обычный мини-макс:

```python
def minimax(node, is_max, st):
    st.nodes += 1
    if isinstance(node, int):          # лист
        st.leaves += 1
        return node, []
    best_val = float('-inf') if is_max else float('inf')
    best_path = []
    for i, child in enumerate(node):
        val, path = minimax(child, not is_max, st)
        if (is_max and val > best_val) or (not is_max and val < best_val):
            best_val, best_path = val, [i] + path
    return best_val, best_path
```

Мини-макс с альфа-бета отсечением (в листинге опущены дополнительные счётчики отсечений по уровням MAX и MIN):

```python
def alphabeta(node, is_max, alpha, beta, st):
    st.nodes += 1
    if isinstance(node, int):          # лист
        st.leaves += 1
        return node, []
    best_path = []
    if is_max:
        best_val = float('-inf')
        for i, child in enumerate(node):
            val, path = alphabeta(child, False, alpha, beta, st)
            if val > best_val:
                best_val, best_path = val, [i] + path
            alpha = max(alpha, best_val)
            if beta <= alpha:          # отсечение
                st.cutoffs += 1
                break
    else:
        best_val = float('inf')
        for i, child in enumerate(node):
            val, path = alphabeta(child, True, alpha, beta, st)
            if val < best_val:
                best_val, best_path = val, [i] + path
            beta = min(beta, best_val)
            if beta <= alpha:          # отсечение
                st.cutoffs += 1
                break
    return best_val, best_path
```

Вызов для корня: `alphabeta(tree, True, float('-inf'), float('inf'), st)`.

Проверки корректности, встроенные в программу:

- значения корня у мини-макса и альфа-бета сравниваются (`assert`), при расхождении программа останавливается;
- проверяется, что найденный путь действительно ведёт в лист со значением корня;
- время выполнения измеряется как среднее по 200 повторам (`time.perf_counter`), так как один запуск занимает доли миллисекунды.

## 5. Методика эксперимента

Эксперимент варианта 19: случайная перестановка потомков, 10 запусков.

1. Строится одно дерево (seed = 19): 729 листьев со значениями из \[0; 40\].
2. Для исходного порядка потомков выполняются замеры обоих алгоритмов.
3. Затем 10 раз в **каждом** узле дерева потомки переставляются случайным образом (seed = 1001…1010); значения листьев остаются прежними, меняется только порядок обхода.
4. Для каждого варианта дерева фиксируются: число узлов мини-макса, число узлов альфа-бета, число отсечений, время выполнения и значение корня.
5. По 10 перестановкам вычисляются минимум, максимум, среднее и стандартное отклонение числа узлов.

## 7. Анализ результатов и выводы

1. **Корректность.** Значение корня (15) совпало у мини-макса и альфа-бета во всех 11 запусках, найденные пути ведут в лист с этим значением. Альфа-бета отсекает только те ветви, которые не могут повлиять на результат.
2. **Выигрыш по узлам.** Мини-макс всегда обходит 1093 узла. Альфа-бета при случайном порядке потомков просматривает от 363 до 577 узлов (в среднем 470), то есть экономит от 47 % до 67 % (в среднем 57 %).
3. **Разброс при случайном порядке.** Число узлов при перестановках меняется в диапазоне 214 узлов (σ = 66,4). Причина: эффективность отсечений определяется тем, насколько рано в узле встречается сильный ход — он быстро сужает окно (α, β) и отсекает больше ветвей.
4. **Сравнение с теоретическим минимумом.** При идеальном порядке потомков потребовалось бы 53 листа из 729. При случайном порядке просматривается 206–335 листьев, то есть примерно в 4–6 раз больше минимума, но существенно меньше 729.
5. **Отсечения по уровням.** В среднем 26 отсечений приходится на уровни MAX и 82 на уровни MIN. Отчасти это объясняется структурой дерева: внутренних MIN-узлов в нём 3 + 27 + 243 = 273, а MAX-узлов 1 + 9 + 81 = 91.
6. **Время.** Выигрыш по времени (в среднем 0,447 мс против 0,290 мс, около 35 %) меньше выигрыша по узлам (57 %), поскольку обработка узла в альфа-бета дороже: обновляются α и β и проверяется условие отсечения.
7. **Итог.** Альфа-бета отсечение даёт тот же результат, что мини-макс, при заметно меньшем объёме работы; её эффективность сильно зависит от порядка перебора ходов, поэтому упорядочивание потомков (сильные ходы первыми) — главный способ ускорить поиск.
